<objective>
Make kore-storage's Testcontainers integration tests runnable as a dedicated, fail-loud Gradle task and wire a self-hosted CI job that runs them with a Docker pre-flight check (CI-01, CI-02).

This phase closes the last v0.0.1 CI-correctness gap: the integration tests exist and are `@Tag("integration")` but there is no task that runs ONLY them, and CI never executes them. This plan adds both, and makes a silently-empty tag filter (the exact failure mode that lets a broken filter pass green) impossible.

Purpose: A broken filter or missing Docker daemon must FAIL the build/CI loudly, never pass green silently.
Output: A `integrationTest` Gradle task (CI-01) and an `integration-test` CI job (CI-02).
</objective>

| Boundary | Description |
|----------|-------------|
| CI runner → Docker daemon | The integration job depends on a Docker daemon on `arc-runner-unityinflow` (unverified per STATE.md). This is an availability/config boundary, not an untrusted-input boundary. |

This phase introduces NO new external inputs, network surfaces, auth, or persisted data. The change set is build config (`build.gradle.kts`) and CI config (`ci.yml`) only.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Denial of Service (false signal) | CI integration-test job vs missing Docker daemon | mitigate | `docker info` pre-flight fails the job loudly with a "RUNNER CONFIG ERROR, not a test failure" annotation BEFORE tests run (D-14) — distinguishes infra breakage from a real regression. The pre-flight is a config-error signal, not a security control. |
| T-05-02 | Tampering (silent green) | integrationTest tag filter matching 0 tests | mitigate | `TestListener` + `AtomicInteger` zero-test guard throws `GradleException` on count==0 (D-10), making a broken/empty filter fail loudly both locally and in CI. |
| T-05-SC | Tampering | npm/pip/cargo installs | n/a | This plan installs NO packages (no dependency changes; Testcontainers already present). No package-legitimacy checkpoint required. |
