<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parent LLM → AgentTool.callTool | LLM-supplied JSON (`ToolCall.arguments`) is the untrusted input that triggers a child spawn. |
| recursion depth | each spawn increases depth; unbounded recursion is a DoS vector. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-7-01 | Denial of Service | `AgentTool.callTool` depth guard | mitigate | childDepth = parentDepth+1 checked against maxDepth BEFORE running the child; over-limit → isError=true with NO child loop (D-03/D-08). Unbounded recursive spawning is impossible (HIER-03 / criterion #3). Covered by the D-03 unit test. |
| T-7-02 | Tampering | `parentRunId` lineage | mitigate | parentRunId is taken only from the dispatch-time bind (parent's server-generated agentId), never from `call.arguments`. The LLM cannot forge a parent id. |
| T-7-07 | Tampering / Input Validation | child `input` from `ToolCall.arguments` | mitigate | The single "input" string is parsed defensively from LLM JSON and used only as the child's task input (no eval, no path/command use). ASVS V5: bounded, treated as opaque text. |
| T-7-03 | Denial of Service | runaway sub-agent tree cost | mitigate | maxDepth caps tree size; per-agent budget isolation keyed by AgentTask.id (Phase 6) bounds each child's tokens; child-budget slicing (BUDG-08) is explicitly deferred. |
| T-7-SC | Tampering | npm/pip/cargo installs | mitigate | N/A — zero external packages added (RESEARCH Package Legitimacy Audit: Not applicable). |

No `high`-severity unmitigated threats — planning not blocked.
